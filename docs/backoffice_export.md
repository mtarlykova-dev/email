# Выгрузка событий из бэк-офиса для отчёта по рассылкам

Нужна, чтобы понять, какие письма автоматических цепочек приводят к действиям клиентов: верификации, пополнению, транзакции, выпуску карты.

## Что выгружать

Все события за **последние 90 дней** — каждый раз заново, а не только за прошедшую неделю. Тогда ничего не теряется на стыке недель.

Одна строка — одно событие. Если у клиента было 5 пополнений, достаточно первого (можно и все — отчёт сам возьмёт первое после письма).

| Колонка | Обязательно | Что это | Пример |
|---|---|---|---|
| `email` | да, если есть | email аккаунта | client@example.com |
| `login` | желательно | логин в Capitalist | client123 |
| `id_back_office` | желательно | ID аккаунта в бэк-офисе | 458812 |
| `product` | нет | Capitalist или CardsPro | Capitalist |
| `event` | да | тип события, см. ниже | deposit |
| `event_datetime` | да | дата и время по Москве, до минуты | 2026-11-18 14:32 |
| `amount` | нет | сумма | 500 |

Нужен хотя бы один из `email`, `login`, `id_back_office`; лучше все три.

### Типы событий (`event`)

| Значение | Что значит |
|---|---|
| `kyc_passed` | пройдена верификация KYC |
| `kyb_passed` | пройдена верификация KYB |
| `deposit` | пополнение баланса |
| `transaction` | транзакция (платёж, выплата) |
| `card_issued` | выпуск карты CardsPro |
| `card_topup` | пополнение карты CardsPro |

Время важно до минуты: отчёт сравнивает его со временем клика по письму, и без времени нельзя понять, что было раньше.

## Формат файла

CSV (разделитель `;` или `,`, кодировка UTF-8 или Windows-1251) или Excel (.xlsx), первая строка — названия колонок. Шаблон: [`backoffice_events_template.csv`](../site/templates/backoffice_events_template.csv).

## Куда загружать

Раз в неделю, по понедельникам: открыть отчёт, ввести пароль, в блоке «Конверсии в целевые действия» нажать «Выбрать файл».

Файл обрабатывается только в браузере и никуда не отправляется. **Не загружайте его в GitHub** — репозиторий публичный.
