# Отчёт по триггерным рассылкам Capitalist и CardsPro

Дашборд по сценариям Sendsay: воронка по каждому письму цепочки, динамика по неделям, алерты и сравнение Capitalist / CardsPro × ru / en.

Каждый день в 06:47 МСК GitHub Actions забирает статистику из Sendsay API, сохраняет её в `data/daily.json` (коммитом — так в истории git видно, как менялись цифры) и публикует страницу на GitHub Pages.

В репозиторий попадают только агрегаты по письмам: сколько отправлено, доставлено, открыто, кликнуто, отписалось. Адресов и других персональных данных нет.

## Первый запуск

1. **Settings → Secrets and variables → Actions → New repository secret**
   - `SENDSAY_LOGIN` — логин аккаунта Sendsay
   - `SENDSAY_APIKEY` — API-ключ (Sendsay → Настройки → API-ключи). Ключу достаточно прав на чтение статистики.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. **Actions → «Обновить отчёт» → Run workflow**.

Через пару минут отчёт будет по адресу `https://mtarlykova-dev.github.io/email/`.

## Как поменять сценарии

Файл `config.json`:

```json
"scenarios": {
  "5": { "name": "Welcome Capitalist", "product": "Capitalist", "lang": "auto" }
}
```

Сейчас в отчёте: Регистрация Capitalist (1), Welcome CardsPro (3), Welcome Capitalist (5, вместе со старой EN-цепочкой 4), After KYB Capitalist (6), Реактивация CardsPro (8).

- ключ — ID сценария в Sendsay, номер из адреса `app.sendsay.ru/automation/workflows/<ID>` (число в конце имени выгрузки `stat_uni_…_41276.csv` — это не ID сценария);
- `product` — `Capitalist` или `CardsPro`, по нему работает фильтр и сравнение;
- `lang` — `ru`, `en` или `auto` (язык определяется по теме письма: кириллица → ru).

Сценарии, которых нет в конфиге, всё равно появятся в отчёте как «Сценарий #ID», пока `auto_discover: true`. Чтобы убрать сценарий, добавьте его ID в `exclude_scenarios`.

Если цепочку перенесли в новый сценарий (как Welcome Capitalist (en) → Welcome Capitalist (ru+en) 01.10), не исключайте старый, а склейте его с новым — так история писем сохранится в одних карточках и графиках:

```json
"4": { "name": "Welcome Capitalist (en), до объединения 01.10", "merge_into": "5" }
```

В `data/daily.json` строки остаются с исходным ID, склейка делается только при сборке страницы.

Порядок писем в цепочке — в `letters` у сценария: по каждому языку список фрагментов темы или названия письма по порядку. Так письмо остаётся на своём месте, даже если его переименовали в Sendsay:

```json
"5": { "name": "Welcome Capitalist", "letters": {
  "ru": ["Добро пожаловать в Capitalist", "Агентство, команда или фрилансер", "Тарифы и карты"],
  "en": ["Welcome to Capitalist", "Agency, team, or freelancer", "Fees without surprises"] } }
```

Если `letters` не задан, номер берётся из начала названия («1. …», «(2) …»), а если его нет — по дате первой отправки (в отчёте такое письмо помечено «порядок не задан»). При добавлении нового письма в цепочку допишите его в `letters`.

Как читать карточку письма:

- у CTR и CTOR справа — изменение к прошлому периоду такой же длины (для «Всё время» не показывается);
- у отписок и ошибок — «в норме» или «выше порога»; порог тот же, что у алертов (`unsub_rate_max`, `bounce_rate_max`), но считается за выбранный период, а алерты — за последние `rate_window_days` дней;
- если у письма за период доставлено меньше `display.min_delivered` (50), сравнения не показываются, цифры серые;
- внешние ориентиры (блок `benchmarks`, GetResponse, данные 2023) — серой строкой под карточкой и в таблице внизу страницы. OR не сравнивается: открытия завышены из-за Apple Mail Privacy Protection.

Пороги алертов — в блоке `alerts`:

| Параметр | Что значит |
|---|---|
| `silence_days` | Срочный алерт, если сценарий не отправлял письма столько полных дней подряд, хотя за 4 недели до последней отправки отправлял. В алерте — реальный срок тишины и дата последней отправки |
| `volume_drop_ratio` | Объём за неделю упал ниже этой доли от обычного |
| `bounce_rate_max` | Ошибки доставки письма за `rate_window_days` выше порога (3%: ориентир для триггерных писем 2,4%, для welcome 4%). Один алерт на сценарий со списком писем |
| `unsub_rate_max` | Отписки письма за `rate_window_days` выше порога (0,6%: ориентир для триггерных писем 0,38%, для welcome 0,94%). Один алерт на сценарий со списком писем |
| `rate_window_days`, `min_events` | Окно для ошибок и отписок (14 дней) и минимум событий (3), чтобы одна отписка на малом объёме не давала алерт |
| `or_drop_ratio` | OR письма за 2 недели упал ниже этой доли от OR за 8 недель до этого |

## Загрузить данные вручную

Если API недоступен или нужна история до `start_date`: выгрузите «Экспорт» из сценария в Sendsay и загрузите zip/csv через GitHub (Add file → Upload files) в папку с ID сценария, например `imports/5/` для Welcome Capitalist. Workflow сам разберёт файл, добавит данные и переложит его в `imports/done/5/`.

После первого запуска в сводке workflow (Actions → запуск → Summary) есть таблица «Сценарии из Sendsay API»: какие ID пришли и какие письма в них. Если ID в API не совпали с номерами из адресов, поправьте ключи в `config.json` по этой таблице.

## Как устроено

```
config.json                  сценарии и пороги алертов
scripts/fetch_sendsay.py     Sendsay API (stat.uni) → data/daily.json
scripts/import_csv.py        ручные выгрузки → data/daily.json
scripts/build.py             алерты + сборка _site/ для Pages
site/index.html              сама страница
data/daily.json              агрегаты: день × сценарий × письмо
data/alerts.json             алерты на дату последней сборки
.github/workflows/report.yml расписание, коммит данных, публикация
```

Посмотреть страницу локально на выдуманных данных:

```
python scripts/demo_data.py
python scripts/build.py --data data/demo.json
python -m http.server -d _site 8000
```
